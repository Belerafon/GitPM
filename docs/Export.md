# Экспорт данных

GitPM формирует экспорт из текущего снимка выбранной рабочей копии. Операция доступна
в верхней панели веб-интерфейса, через HTTP и команду `gitpm export`. Экспорт не изменяет
repository state и доступен ролям с правом чтения.

## Имена файлов и снимок

Базовое имя имеет вид `gitpm-YYYYMMDD-<short-hash>`, где дата и первые восемь символов
берутся из `HEAD`-коммита:

- `gitpm-20260725-deadbeef-portfolio.pdf`;
- `gitpm-20260725-deadbeef-static.html`;
- `gitpm-20260725-deadbeef-csv.zip`;
- `gitpm-20260725-deadbeef-repository.zip`;
- `gitpm-20260725-deadbeef-repository-with-git.zip`.

В отрисованные форматы попадает текущее содержимое рабочей копии, включая
незакоммиченные изменения. Хеш в имени фиксирует базовый `HEAD`, а не утверждает,
что рабочая копия чистая.

## Форматы

### PDF

По умолчанию включены разделы «Проекты» и «Люди». Дополнительно можно выбрать:

- подробную страницу для каждого проекта с этапами и задачами;
- отдельную страницу Ганта для каждого проекта.

Две сводные страницы повторяют состав данных стандартных web-реестров и включают только
активные сущности:

- «Проекты»: название, ID и краткое описание, статус, ответственный, количество активных задач
  и этапов, срок и рассчитанный на дату экспорта риск; проекты сохраняют группировку из web;
- «Люди»: сотрудник, проекты, в которых он является ответственным или исполнителем, команды,
  недельная ёмкость и рабочий календарь.

На странице проектов также выводятся сводные количества активных проектов, задач и этапов,
а также завершённых задач. Названия статусов, даты, числа, единицы ёмкости и рассчитанные риски
форматируются для выбранного языка. Для читаемости расширенных таблиц PDF создаётся в альбомной
ориентации.

Текст формируется на выбранном языке (`ru` или `en`); встроенный шрифт поддерживает
кириллицу.

### Статический HTML

Один автономный HTML-файл содержит проекты, людей, команды, календари, подробности
проектов, доски и представления Ганта. В нём нет форм, кнопок редактирования,
публикации и других мутаций. Навигация реализована обычными ссылками внутри файла.
Пользовательский Markdown выводится как безопасный текст.

### CSV

ZIP содержит отдельный UTF-8 CSV с BOM для каждой найденной repository schema:
конфигурации, проекты, этапы, задачи, люди, команды, календари, сохранённые
представления и комментарии (если они существуют). Массивы и вложенные значения
кодируются JSON внутри CSV-ячейки.

### Repository ZIP

Вариант без Git содержит рабочую копию как есть, кроме `.git`. Символические ссылки
сохраняются как ссылки и никогда не разыменовываются за пределы репозитория.

Вариант с Git добавляет переносимую `.git`-историю. Для worktree это новая локальная
копия истории, а не служебный `.git`-указатель на каталог GitPM. URL `origin`
намеренно удаляется: экспорт не должен переносить локальные пути или потенциальные
учётные данные. Рабочие файлы, включая незакоммиченные и untracked, берутся из
экспортируемой рабочей копии.

## CLI

```bash
gitpm export --format pdf --locale ru
gitpm export --format pdf --section projects --section people \
  --section project-details --section gantt
gitpm export --format html
gitpm export --format csv
gitpm export --format repository
gitpm export --format repository --include-git
```

В worktree-режиме нужен `--draft <id>`. В direct-режиме используется выбранный
checkout. По умолчанию файл записывается в текущий каталог под сгенерированным именем.
`--output <path>` задаёт другой путь. Существующий файл не перезаписывается без
явного `--force`.

## HTTP

```text
GET /api/drafts/:draftId/export
  ?format=pdf|html|csv|repository
  &locale=ru|en
  &sections=projects,people,project-details,gantt
  &include_git=true|false
```

Ответ — бинарное вложение с `Content-Disposition`, `Content-Type` и
`Cache-Control: no-store`. Неподдерживаемые параметры возвращают стабильные
`EXPORT_*` error codes. Невалидная структура repository не отрисовывается и
возвращает `EXPORT_REPOSITORY_INVALID`.
