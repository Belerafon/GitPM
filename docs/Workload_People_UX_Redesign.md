# Переработка разделов «Состав» и «Загрузка»

Нормативное описание семантики `/people` и `/workload`. Реализация обязана
совпадать с этим контрактом, а не только с подписями.

## Проблема

`/people` — справочник Person и Team. `/workload` — аналитика часов. Фильтры
Project, Milestone и Team выглядели как фильтры строк, но команда отбирала
Tasks и оставляла всех людей. Этап без проекта смешивал чужие этапы. Период
«следующие N недель» начинался с самой ранней задачи. Счётчики говорили о
задачах, хотя на экране — люди.

## Информационная архитектура

Раздел «Команда» открывается на **Составе** (`/people`), не на теплокарте.

1. **Состав** (`/people`) — кто работает, команды, норма, календарь.
2. **Загрузка** (`/workload`) — сколько выбранные люди заняты выбранными работами в календарном окне.
3. **Отсутствия** (`/vacations`).

На `/people` локальные вкладки **Сотрудники** и **Команды**. Формат имени по
умолчанию живёт в Settings → People, не над справочником.

## Две независимые области `/workload`

### Кого показывать (строки)

- все активные люди, одна команда или один человек из URL;
- без мультивыбора команд и произвольного picker людей;
- Team = `active people ∩ team.members`;
- общий Task не добавляет соисполнителя вне команды в строки;
- люди без активного календаря не пропадают молча: они в `person_census` и в предупреждении.

### Какие работы учитывать (часы)

- Project ограничивает Tasks, не людей;
- Milestone недоступен без Project и содержит только этапы этого проекта;
- пустые строки остаются, пока явно не выбрано «только с работой».

### Когда считать

- старт по умолчанию — текущая неделя;
- 4 / 8 / 12 недель от старта, кнопки предыдущий / эта неделя / следующий;
- окно сериализуется в URL (`from`, `weeks`) и не является saved-view (ADR 0005).

## Публичный контракт CLI / HTTP / export

`--team` и `--person` (query `team`, `person`) ограничивают **строки**.
`--project` и `--milestone` ограничивают **Tasks**. `--from` и `--weeks`
задают календарное окно; без них CLI сохраняет горизонт по датированным Tasks.

JSON-отчёт содержит `person_census`: `total_active`, `scoped`, `calculable`,
`without_calendar`.

## Приёмка

1. Выбор команды меняет набор строк на активных участников команды.
2. Общий Task не добавляет постороннего в строки.
3. Выбор Project меняет часы, но не состав явно выбранной команды.
4. Milestone нельзя выбрать без Project.
5. «Следующие 8 недель» начинается с текущей недели и содержит ровно восемь недель.
6. Видны shown / scoped / total, отсутствие календаря объяснено.
7. Перезагрузка сохраняет фильтры через URL `/workload`, не через saved-view.
8. Из Person и Team можно открыть предфильтрованный Workload.
9. `/people` не показывает одновременно длинные редакторы сотрудников и команд.
10. Блок качества Tasks вторичен относительно состояния людей.
